# НарядAI — умные производственные наряды

НарядAI убирает бумажные наряды из цеха. Мастер выдаёт работу с телефона за минуту, исполнитель ведёт её по статусам с фото, искусственный интеллект проверяет результат, а руководитель видит живую картину смены и находит больные места в аналитике. Всё это — одно приложение на русском и казахском, которое ставится на телефон как обычное мобильное приложение.

Проект подключён к настоящему бэкенду — никаких нарисованных данных: каждый статус, каждая кнопка и каждая цифра приходят с сервера в реальном времени.

## Как это работает — один день из жизни смены

Утро. Мастер открывает **«Смену»** и видит: сколько нарядов выдано, что выполнено, что горит красным — просрочка, какое оборудование простаивает. На насосе течёт масло — аварийная ситуация. Мастер жмёт «Выдать наряд», выбирает насос, ставит приоритет «Аварийный», описывает проблему текстом или голосом — и тут подключается ИИ: **подсказывает лучшего исполнителя** с оценкой уверенности («Свободен, чинил такой насос 4 раза»). Мастер подтверждает — наряд у рабочего.

У исполнителя на телефоне — **свой простой экран**: что в работе сейчас, что в очереди, что срочное. Открыл наряд, нажал «Принять», потом «Начать». Заменил уплотнение, долил масло — сфотографировал результат («после»), описал, что сделано, выбрал шифр неисправности из справочника и нажал «Завершить». Всё, телефон можно убирать.

Дальше работает ИИ-приёмка: система проверяет полноту отчёта, расход материалов против нормы, сроки и фотографии — и выносит вердикт с оценкой. Мастер получает уведомление, открывает **«Приёмку»**: видит вердикт, фото «до/после» рядом, что хорошо, а что улучшить. Согласен — закрывает одной кнопкой. Не согласен — возвращает на доработку с комментарием, и рабочий видит её у себя.

Вечером руководитель открывает **«Аналитику»**: процент в срок, динамика, топ проблемного оборудования с оценкой, простои, расход материалов, рейтинг исполнителей и главное — **ИИ-инсайты**: «насос ГрАТ-250 ломается чаще нормы — проверьте подшипниковый узел». По инсайту можно сразу создать плановый наряд.

Администратор в том же приложении управляет справочниками: участки, оборудование, бригады, сотрудники (создание, смена роли и участков, сброс ПИНа, разблокировка), шифры, материалы, нормы и причины.

## Что умеет приложение

- **4 роли — 4 разных интерфейса**: исполнитель (крупные кнопки для работы в перчатках), мастер (смена + живая доска-кабан), руководитель (аналитика), администратор (справочники и люди). После входа каждый попадает на свой экран.
- **Живой жизненный цикл наряда**: выдан → принят → в работе → проверка ИИ → закрыт, с ветками «пауза», «очередь», «отклонён», «доработка». Кнопки всегда соответствуют тому, что разрешено прямо сейчас.
- **ИИ как советник, а не начальник**: подбор исполнителя, подбор шифра неисправности, проверка закрытого наряда, поиск закономерностей. У каждой подсказки — уверенность и объяснение, решение всегда за человеком.
- **Всё обновляется само**: принял рабочий наряд — карточка на доске мастера переехала без перезагрузки. Уведомления, счётчики, бейджи — в реальном времени.
- **Работает в цеху, а не только в офисе**: установка на телефон, крупные touch-зоны, голосовой ввод, сжатие фото перед отправкой, очередь действий без связи (примет — отправит позже, дублей не будет).
- **Два языка**: русский и казахский, переключаются в шапке.

## Технологии

React 19 + TypeScript + Vite, данные через типизированный API-клиент и TanStack Query, состояние в Zustand, схемы в Zod, локализация i18next (ru/kk), графики Recharts, стили Tailwind CSS 4, обновления по WebSocket, PWA (установка на телефон) и сборка под Tauri (десктоп/Android).

## Быстрый старт для разработчика

```sh
npm install
npm run dev      # http://localhost:5173
```

## Конфигурация

Адрес backend задаётся только переменными окружения (`.env.development`, `.env.production`) — при переезде код не меняется:

| Переменная | Назначение |
|---|---|
| `VITE_API_URL` | базовый адрес REST (`http://localhost:8080/api/v1`) |
| `VITE_WS_URL` | адрес WebSocket (`ws://localhost:8080/api/ws`) |

Для локальных адресов используйте `.env.local` (не попадает в репозиторий).

## Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер Vite |
| `npm run build` | production-сборка + service worker (PWA) |
| `npm run typecheck` | проверка типов (`tsc --noEmit`) |
| `npm run lint` | линтер `oxlint` |
| `npm run test` | unit-тесты (Vitest) |
| `npm run test:e2e` | сквозные тесты (Playwright, нужен запущенный backend) |
| `npm run check:contract` | сверка доступных путей API с ожидаемым контрактом |
